- 2MB 미만 blob을 텍스트로 검사했습니다. 큰 바이너리/사진/영상 내용은 전수 검토하지 않았습니다. 패턴 검색은 비밀값 부재를 보장하지 않습니다.

## 함께 정리할 항목

- `backend/.gitignore`의 `backend/uploads/`는 파일 위치 기준으로 잘못 지정되어 실제 `backend/uploads/`를 무시하지 못합니다. 해당 파일에서는 `/uploads/`가 맞습니다. 현재 로컬 작업 트리의 업로드 파일은 미추적 상태이며 `git add .` 시 다시 포함될 수 있습니다. ignore 수정만으로 과거 기록은 삭제되지 않습니다.
- `backend/app/routers/auth.py:36`, `backend/app/utils/token.py:9`에 고정 JWT 기본키 `dev_secret`이 있습니다. 서비스 환경에서는 키가 없을 때 실행을 거부하도록 변경하고 충분히 강한 키를 주입해야 합니다. 이 기본값이 실제 서비스에서 사용됐는지는 이번 검사로 확인하지 않았습니다.
- `app/index.js`는 카카오 토큰·로그인 응답·JWT를 로그로 출력합니다. 디버깅 로그·화면 녹화·공유 로그를 통해 자격증명이 노출되지 않도록 토큰 출력 제거가 필요합니다.
- 예전 `app/(tabs)/recycle/index.js`에 카카오 JavaScript 키가 있습니다. `app.json`의 카카오 Native 키와 OAuth client ID도 앱에 배포되는 식별자이므로 서버용 비밀키와 동일하게 판단하지 않습니다. 허용 도메인·플랫폼·서명 제한을 확인해야 합니다.
- `backend/.DS_Store`, `backend/app/.DS_Store`가 추적되어 있으며, 과거 기록에는 `backend/venv/`도 있습니다. 공개에 불필요한 로컬 파일입니다.
- 저장소 최상위 LICENSE/NOTICE를 확인하지 못했습니다. 팀원의 공개 동의, 이미지·애니메이션·아이콘·CSV의 출처/재배포 조건, AI Hub 학습 데이터 및 모델 배포 조건을 확인해야 합니다.
- 케어라벨 모델 `backend/app/models/best.pt` 내부 메타데이터에는 AGPL-3.0이 명시돼 있습니다. Ultralytics는 기본적으로 해당 라이선스로 코드와 학습 모델을 제공한다고 안내합니다. 배포 형태에 맞는 조건을 확인한 뒤 프로젝트 라이선스와 고지를 정해야 하며, 임의로 MIT 등을 붙여서는 해결되지 않습니다. [공급자 라이선스 안내](https://www.ultralytics.com/license)

전화번호 패턴으로 잡힌 `app/signup.js`의 값은 형식 안내/placeholder였으며 개인정보 유출로 집계하지 않았습니다. README의 `DB_USER:DB_PASSWORD` 예시도 실제 자격증명으로 집계하지 않았습니다. 가상환경 패키지 문서의 예시 비밀번호는 제외했습니다.

## 권장 순서

1. 과거/현재 DB 자격증명과 JWT 키의 실제 사용 여부를 확인하고 필요한 키를 교체합니다.
2. 현재 코드·ignore·로그와 자산의 공개 권리를 정리합니다.
3. 팀과 협의하여 기존 저장소의 모든 공개 참조에서 민감 기록을 제거하거나, 검토한 파일만 넣은 새 공개 저장소를 만듭니다. 기존 저장소의 이력 재작성·강제 push는 협업에 영향을 주므로 이번 작업에서 실행하지 않았습니다.
4. GitHub 웹/API 접근을 확보해 PR/이슈, Actions 로그/아티팩트, Releases를 별도로 검사합니다. 전환 직전 브랜치 목록도 다시 확인합니다.
5. 정리 후 재검사하고 public 전환을 결정합니다.

GitHub도 비밀값은 우선 폐기/교체할 것을 권고합니다. 공개 전환 시 Actions 기록/로그도 공개될 수 있습니다.
