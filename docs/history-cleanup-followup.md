# 이력 정리 후 팀 작업 및 GitHub 후속 처리

## 적용 결과

2026-09-10 사용자가 28개 원격 브랜치의 이력 교체와 재-clone 필요성을 명시적으로 승인한 뒤, 백업·개별 SHA 검사·원자적 push로 정리된 이력을 반영했습니다. 브랜치 이름 28개는 모두 유지했으며, 실제 커밋이 바뀐 브랜치는 26개입니다. 태그는 없었습니다.

독립된 원격 bare clone에서 브랜치 이력 130개 커밋과 2MB 미만 blob 후보 868개를 검사했습니다. 제거 대상 경로와 검사한 비밀값 패턴의 추가 검출은 0건입니다. GitHub의 PR 참조는 아래처럼 별도 남아 있습니다.

## 팀원 안내

- 기존 작업 폴더는 비공개 백업으로 보관하고 새 폴더에 저장소를 clone합니다. 기존 폴더에 pull/merge한 뒤 그대로 push하지 않습니다.
- 아직 커밋하지 않은 작업은 먼저 별도로 보관하고, 새 폴더에 필요한 코드 변경만 검토해서 적용합니다. 환경파일·업로드·가중치는 커밋하지 않습니다.
- 환경파일과 허가받은 모델 파일은 개인별로 별도 준비합니다. JWT 키를 교체한 서버에 연결하는 앱은 다시 로그인해야 합니다.
- `python3 scripts/check-public-history.py main`으로 제외 대상 경로가 과거 기록에 다시 포함되지 않았는지 검사할 수 있습니다. 이 검사는 파일 경로만 확인하며 완전한 비밀값·라이선스 검사가 아닙니다.
- 현재 작업 Mac은 main과 대응되는 로컬 브랜치를 새 이력으로 맞췄습니다. 매핑되지 않은 로컬 `backup/*` 참조 3개는 삭제하지 않고 보존했으므로 외부에 올리지 않습니다. 원래 이력은 Git에서 제외된 `.local-backups/public-release-20260910/`의 bundle에도 보관합니다.

## 남은 상태와 공개 판단

1. 원격 브랜치에서 `backend/.env`는 제거됐지만 과거 파일 객체는 인증된 GitHub API에서 여전히 조회 가능합니다. GitHub PR 참조도 48개가 남아 있으며, 정리 도구는 그중 47개 참조가 영향을 받는다고 보고했습니다.
2. 이슈 #23의 첨부 링크는 본문에서 제거했지만 외부 첨부 원본과 편집 이력의 제거는 확인되지 않았습니다. 이후 사용자가 이미지 노출은 문제없다고 확인하여, 사진 노출 우려는 공개 보류 사유에서 제외했습니다.
3. 현재 앱 자산 130개 중 22개는 공식 배포본과 대조하고 라이선스 고지를 추가했습니다. 나머지 108개 자산의 재배포 권한은 미확인입니다. 팀 공개 동의는 이후 사용자가 확인했습니다. 모델 가중치를 제외한 것만으로 모델을 사용하는 코드의 라이선스 조건까지 해결되지는 않습니다.

## 기존 GitHub Support 초안 (미전송·사용자 판단 반영 전)

비공개 저장소 `juuu-sung/Re-wear-project`에서 민감한 환경파일, DB 접속정보 및 사용자 미디어가 과거 이력에 포함된 것을 확인했습니다. 관련 로컬 DB 비밀번호와 JWT 키는 교체했으며 git-filter-repo 2.47.0으로 모든 원격 브랜치 이력을 정리했습니다. 그러나 정리 후에도 과거 환경파일 객체가 API에서 조회됩니다.

과거 PR 참조·캐시·도달 불가능한 민감 객체와 사용자 업로드 첨부의 제거 가능 여부를 확인해 주세요. PR 참조 47개가 이력 정리의 영향을 받았고, 추가로 이슈 #23의 첨부 링크를 제거했습니다. 필요한 첫 변경 커밋, 영향받은 PR 목록 및 객체 식별자는 비공개 지원 요청에서 제공할 수 있습니다. 비밀번호 값이나 미디어 원본은 본문에 첨부하지 않겠습니다.

GitHub Support는 자격증명 교체만으로 위험을 해소할 수 있는 경우 추가 삭제를 지원하지 않을 수 있습니다. 지원 결과와 잔여 개인정보·자산 권한 확인을 마친 뒤 공개 여부를 결정합니다. [GitHub 공식 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

### 제출 준비 상태

2026-09-10 사용자 로그인과 2단계 인증을 거쳐 지원 양식까지 열었습니다. 이후 사용자가 지원 문의 없이 Public 전환을 요청하여 요청은 전송하지 않았습니다. 최초 변경 커밋 2개와 변경 후 ID, 영향받은 PR 번호 47개, 남은 파일 객체 ID 및 이슈 첨부 URL 1개를 포함한 실제 제출용 문서를 `.local-backups/public-release-20260910/github-support-request.txt`에 준비했습니다. 이 파일은 Git에서 제외하고 소유자만 읽고 쓸 수 있게 저장했습니다. 비밀번호·토큰 값이나 사진 원본은 포함하지 않았습니다. 첨부 URL은 다시 공개 저장소 문서에 복사하지 않습니다.

요청 내용의 제출 승인 후 비공개 지원 창구에 제출하고, 접수 번호와 처리 결과를 확인해야 합니다. 현재 본문에서 링크가 사라진 것과 GitHub의 원본 객체·편집 이력이 삭제된 것은 서로 다른 상태입니다.

사용자가 이미지 노출은 문제없다고 확인했으므로 기존 초안의 사진 공개 우려를 현재 사용자의 우려로 제시하지 않습니다. Support 문의는 공개 전환의 필수 절차가 아니며, 제출은 진행하지 않았습니다. 과거 비밀번호·키의 폐기로 접속 위험이 해결될 수 있다는 GitHub 안내와 원본 객체가 남아 있다는 사실은 구분합니다. 추가 문의를 하게 된다면 실제 남은 위험에 맞춰 초안을 먼저 수정해야 합니다.

## 최종 사용자 요청

사용자는 팀원에게 코드 공개 동의를 받았다고 확인하고 저장소를 Public으로 전환하도록 명시적으로 요청했습니다. 라이선스 고지 및 검토 문서를 먼저 원격 main에 반영한 뒤 공개 설정을 변경하는 순서로 진행합니다. 지원 요청은 제출하지 않습니다.
